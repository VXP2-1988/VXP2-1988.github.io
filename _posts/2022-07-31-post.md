Today I refamiliarized myself with the ticketing project. Thankfully, I use git properly so it didn't take long to retrace the thread of what I was doing a month ago.

I cleaned up my tests and implemented a user deletion button and method. Also retricted user deletion and access to site settings to admins only. Right now it just returns a generic 403 error if a regular user somehow makes a request, and a generic 404 error if the user doesn't exist. Also disallowed deletion of admin accounts. 

I plan to only give admin to my client and myself, and the use case I was given didn't include registering multiple admins.

Tomorrow I'll work on password reset, which is the last major issue that needs addresssing. I also need to connect the generic invoice form to the database, as of now only the grocery invoice form functions fully. 

### Future Plans
In future, I also want to change the way passwords work for new users. Right now the admin sets a password for the new user they create and that has obvious problems. For this specific case it's not a huge issue, but it's good practice to fix this sort of problem even when it's a little overkill. The future system will simply generate a temporary invite password that will be sent to a provided email. On the first login, the user will be prompted to change their password to a more permanent solution. Could also have it generate an invite link and set password that way.

In future I'd also like to look into locally hosting this server. My client likes things local and on-site, and would appreciate not having to rely on Heroku. I have a Raspberry Pi 2 that I'm not using, will investigate further.

Lastly and on the subject of local hosting, my client would also like to use their own SMTP server. Currenly the site is using Gmail for all the message creation.
